GraphUnslopify

An MCP server that turns a semantic figure specification into runnable matplotlib code.

An agent says what the figure means. The generator decides how it is drawn. There is no colour, line width, or font size anywhere in the spec, which is the point. If an agent could set them, every figure in your paper would disagree with every other one.

Your data never leaves your machine. You get back a Python script that reads your own CSV.

The spec

{
  "kind": "line",
  "x": { "field": "epoch", "label": "Training epoch" },
  "y": { "field": "accuracy", "label": "Test accuracy", "unit": "%" },
  "group": "model",
  "aggregation": "mean",
  "series_order": ["baseline", "ours"],
  "emphasis": { "series": "ours" }
}

series_order pins colour assignment so a model keeps its colour across every figure. emphasis names the series you are arguing for and the generator foregrounds it, muting the rest. aggregation collapses repeated x values, which is what a curve measured over several seeds needs.

Endpoints

PathMethodPurpose
/api/mcpGET, POST, DELETEMCP Streamable HTTP
/api/convertPOSTSame translation without MCP, for curl
/api/healthGETLiveness

Connect an MCP client

claude mcp add --transport http graph-unslopify \
  https://json-translator-three.vercel.app/api/mcp

Or curl it

curl -X POST https://json-translator-three.vercel.app/api/convert \
  -H 'content-type: application/json' \
  -d '{"kind":"line",
       "x":{"field":"epoch","label":"Epoch"},
       "y":{"field":"acc","label":"Accuracy"}}'

Line, scatter, and bar for now. Twelve checks run on the spec before anything is drawn. Source on GitHub.
